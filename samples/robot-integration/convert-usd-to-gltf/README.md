# USD 转 glTF 导入 ME — 用户须知

> 适用场景：将 NVIDIA Isaac Sim / Omniverse 中制作的 USD 资产，转换为 ME 可用的 glTF 格式。

---

## 一、执行方式

在装有 **Isaac Sim 5.1.0**（Windows、Linux 均可）的机器上运行转换脚本，生成 glTF 文件后导入 ME。

### 使用限制

- **显卡驱动**：595.x 驱动与 Isaac Sim 5.1.0 存在兼容性问题。
  - Windows：建议使用 **580.88 – 594.x**
  - Linux：建议使用 **580.65.06**
- **场景规模**：USD 文件建议总共不超过 **500 mesh、1000万 面片**，避免性能影响。

| 我的场景是…… | 能转吗？ | 需要做什么？ |
|---|---|---|
| 静态模型展示（机器人摆拍、产线布局、室内场景） | ✅ 能转 | 直接执行脚本 |
| 带贴图/材质的模型（PBR 材质、UDIM 高精贴图） | ✅ 能转 | 直接执行脚本 |

| 带有逻辑控制的场景（OmniGraph 节点图） | ❌ 不能转 | 需在 ME 中重新开发逻辑 |

## 三、转换后，哪些东西能保留？哪些会丢失？

### ✅ 会保留（视觉层）

| 你有的 | 转换后 | 说明 |
|---|---|---|
| 模型网格（Mesh） | ✅ 完整保留 | 模型形状、三角面、顶点 |
| 模型位置/旋转/缩放 | ✅ 保留 | 摆放位置不变 |
| UV 贴图坐标 | ✅ 保留 | 贴图不会错位 |
| PBR 材质（颜色/金属/粗糙） | ✅ 保留 | 视觉外观一致 |
| 贴图（BaseColor/Normal/粗糙度等） | ✅ 保留 | 纹理图片会单独输出 |
| UDIM 高精贴图 | ✅ 保留（已拆分） | 视觉上一致，内部会拆成多张普通贴图 |
| 顶点色（Vertex Color） | ✅ 保留 | 模型自带的颜色 |
| 一个模型绑定多个材质 | ✅ 保留 | 不同部分显示不同材质 |

### ⚠️ 会变化（视觉近似）

| 你有的 | 转换后 | 说明 |
|---|---|---|
| 模型法线（Normal） | ⚠️ 可能被重新计算 | 表面光滑度可能有轻微差异 |
| 多套 UV（UV0/UV1） | ⚠️ 可能映射有变 | 依赖 exporter 的映射关系 |
| 贴图平铺/偏移/旋转 | ⚠️ 不保证生效 | 由 Nvidia exporter 实现，可能丢失或表现不一致 |
| 实例化（多个相同物体） | ⚠️ 会被展开 | 视觉不变，但文件变大 |
| USDPreviewSurface、OmniPBR、OmniGlass、OmniSurface 材质 | ⚠️ 存在材质降级 | 降级为 ME 的 StandardPBR，不是所有属性都可以导出（例如 glass、毛绒效果） |

### ❌ 会丢失（仿真/逻辑层）

| 你有的 | 转换后 | 替代方案 |
|---|---|---|
| 动画（移动/旋转/骨骼） | ❌ 全部丢失 | 在 ME 中重新 K 动画 |
| 表情/形变（BlendShape） | ❌ 丢失 | 在 ME 中重新制作 |
| 物理碰撞体 | ❌ 丢失 | 在 ME 中重新生成碰撞盒 |
| 刚体/关节/动力学 | ❌ 丢失 | 在 ME 中重新配置物理属性 |
| 物理材质（质量/惯性） | ❌ 丢失 | 在 ME 中重新设置 |
| 机器人关节（Articulation） | ❌ 丢失 | 在 ME 中用组件重建 |
| 灯光（点光/聚光/面光） | ❌ 丢失 | 在 ME 中重新布光 |
| 相机 | ❌ 丢失 | 在 ME 中重新放置 |
| 逻辑图（OmniGraph） | ❌ 丢失 | 在 ME 中重新编程 |
| 声音驱动（Audio2Face） | ❌ 丢失 | 在 ME 中重新实现 |
| 隐藏对象 | ❌ 不会导出 | 如需显示请先取消隐藏 |

## 四、转换后，我需要上传哪些文件？

> ⚠️ **重要提醒：glTF 不是单文件！**

转换完成后，你会得到一个文件夹，里面包含：
你的模型名/
├── 你的模型名.gltf ← 主文件（描述场景结构）
├── 你的模型名.bin ← 顶点数据（必不可少）
└── textures/ ← 贴图文件夹
├── 1001.png ← BaseColor
├── 1002_normal.png ← 法线贴图
└── ...


> ⚠️ **上传/拷贝时，必须把整个文件夹一起拷贝，不能只传 `.gltf` 文件！**
> 如果缺少 `.bin` 或纹理，模型会显示为白模或直接导入失败。

## 五、转换时需要注意什么？（操作须知）

| 注意事项 | 说明 |
|---|---|
| 文件命名 | 文件名的第一个点号前的部分必须唯一。例如 `Rack.Small.usd` 和 `Rack.Big.usd` 会都变成 `Rack.gltf`，相互覆盖！ |
| 输出目录 | 输出目录如果已存在，会自动删除重建。请勿把输出目录设置为重要文件所在目录。 |
| 纹理路径 | 请确保 USD 中引用的纹理文件路径有效。脚本会自动修复 `.jpg→.png` 扩展名不匹配问题，但无法修复“文件根本不存在”的情况。 |
| 关键贴图缺失 | 如果 UDIM 的 BaseColor/Opacity 等关键贴图缺失，该 tile 的材质会创建失败（模型显示为白模）。 |
| 可选贴图缺失 | Normal/Roughness/Metallic 等非关键贴图缺失时，会自动使用材质默认值，不阻断导出。 |
| 执行时间 | 大型场景转换可能耗时较长。脚本会打印进度条，请耐心等待。 |

## 六、如何检查转换是否成功？

执行脚本后，检查终端输出：

| 日志关键词 | 含义 | 下一步 |
|---|---|---|
| `File loaded successfully` | USD 加载成功 | 继续 |
| `Mesh ... skipping...` | 某些面被跳过 | 检查是否是可接受的范围 |
| `UDIM MATERIAL FAILED` | 关键贴图缺失，该 tile 材质创建失败 | 补上贴图后重新导出 |
| `File export completed, task finished` | 导出成功 | 去输出目录拿文件 |

## 七、常见问题（FAQ）

### Q1：我有 `.usdz` 文件，可以直接转吗？
可以。脚本支持 `.usd` / `.usda` / `.usdc` / `.usdz` 四种格式。但建议先将 `.usdz` 解压成 `.usd` 再转，避免纹理路径解析问题。

### Q2：为什么我的模型导入 ME 后没有材质/是白模？
可能原因：
1. 关键贴图（BaseColor）缺失 → 检查纹理文件是否齐全
2. 材质类型不被支持（如任意 MDL Shader）→ 需在 Isaac Sim 中改用 `UsdPreviewSurface` 或 `OmniPBR`
3. 上传时漏了 `.bin` 或贴图文件 → 确认整个文件夹一起拷贝

### Q3：我的机器人能转吗？里面有关节和物理。
视觉上可以转（外观、材质都会保留），但物理和关节会丢失。导入 ME 后，你需要重新为它添加关节组件、碰撞体、物理材质。

### Q4：我的场景里有动画，能转吗？
不能。当前脚本会主动关闭动画（避免导出崩溃）。如果需要动画效果，请在 ME 中重新制作。

### Q5：转换后的模型，和原版的渲染效果会完全一样吗？
视觉上基本一致，但可能存在以下细微差异：
- 法线可能被重新计算（光滑度略有不同）
- 灯光不保留（需要重新打光）
- 复杂 MDL 材质可能退化（变成标准 PBR）
