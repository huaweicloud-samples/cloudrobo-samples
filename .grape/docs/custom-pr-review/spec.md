# Spec Document — Issue #3 定制PR检视（多门禁检视）

> 来源：Issue #3 评论 6140741130（issue agent 交付）+ 评论 6183893873（Chat Agent 门禁扩展需求）| v2.0.0 | 2026-10-15

## Objective
- **构建什么**：将 custom-pr-review 从 v1.1.0（仅敏感词校验）扩展为 v2.0.0（7 类门禁检视），新增代码质量/编译构建/依赖漏洞/License 合规/密钥泄露/文档规范 6 类门禁，敏感词校验沿用 v1。
- **为什么**：防止内部域名/IP/密钥/License 问题随 PR 变更外泄或引入，阻断级问题须修复才能合入，警告级仅提示。
- **用户**：本仓库 PR 作者与审查者。
- **成功标准**：7 类门禁全部执行并按分级报告；阻断级（License/密钥/编译）标注 ❌，警告级（代码风格/文档/依赖/敏感词）标注 ⚠️。

## Scope

### In Scope
- v1 敏感词校验（沿用，不阻断）
- v2 新增 6 类门禁：代码质量（ruff+black/clang-format+clang-tidy）、编译构建（py_compile/ROS2）、依赖漏洞（pip-audit）、License 合规（缺失/改坏/不兼容）、密钥泄露（正则检测）、文档规范（mdl/yamllint）
- 分级策略：阻断级（License/密钥/编译）❌ + 警告级（代码风格/文档/依赖/敏感词）⚠️
- 工具缺失时降级为 SKIP+备注，不中断检视

### Out of Scope
- 不直接阻断 PR 合入（由 GitHub Actions required checks 实现，非本技能职责）
- 不校验 PR 标题/描述
- 不修改 .github/workflows/ci.yml（超出技能目录范围，需单独实施）

## Technical Approach

### 方案概述
在现有 PR 订阅 QA 审查技能的检视流程中，于「生成检视评论」前插入敏感词校验步骤：拉取 PR diff（git diff 文件+行号定位）→ 扫描变更文件内容 → 命中清单附加到检视评论。

### 实现路径
1. **定位目标技能**：在 grape 平台官方技能库中定位当前 PR 订阅 QA 审查所用技能（qa 类）；确认其检视评论生成入口。
2. **新增敏感词校验模块**：内置词表（huawei.com/codehub/myhuaweicloud.com）+ IP 正则（含公网/内网）；仓库内可扩展词表文件（存在则合并，允许覆盖）。
3. **diff 解析**：基于 PR diff 定位变更文件与新行号，仅扫描变更文件内容，输出 (文件, 行号, 命中词) 三元组。
4. **评论组装**：命中>0 时在检视评论末尾附加「敏感词校验结果」段落；命中=0 时不附加。
5. **回归验证**：既有检视结论、评论格式、订阅通知链路不受影响。

### 关键设计决策
| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 改造 vs 新建 | 新建独立技能 / 改造现有 QA 审查 | 改造现有 | 用户明确「不新建独立技能」 |
| IP 识别方式 | 词表枚举 / 正则 | 正则 | IP 任意取值无法枚举，正则含公网/内网 |
| 命中动作 | 评论报告 / 门禁阻断 | 评论报告 | 用户明确「仅评论报告，不阻断合入、不作为门禁」 |
| 校验范围 | PR 全量（标题/描述/文件）/ 仅变更文件内容 | 仅变更文件内容 | 用户明确缩小范围 |
| 行号定位 | 文件全量行号 / diff 新行号 | diff 新行号 | 与 PR 变更视图行号一致，便于审查者跳转 |

## Acceptance Criteria
- [ ] PR 触发审查后，变更文件中出现内部域名或任意 IP 时，检视评论准确列出所有命中位置（文件+行号）
- [ ] 未命中敏感词时，不附加敏感词报告，原审查结论与评论格式不变
- [ ] 仅评论报告：不阻断 PR 合入、不作为门禁、不影响原审查结论
- [ ] 词表可通过仓库内文件扩展（追加/覆盖内置词表）
- [ ] 所有现有测试通过；新增测试覆盖敏感词校验功能（命中/未命中/词表扩展）
- [ ] 运行验证由 sre Agent 执行，coding 阶段不执行长驻前台命令

## Risks & Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| 官方技能不可 fork/定制入口未开放 | Med | coding 阶段先定位技能资产与定制机制，不可行时回退为仓库内 overlay/包装方案 |
| IP 正则误报（如版本号 1.2.3.4、CIDR） | Med | 正则加边界约束；命中报告标注「疑似 IP」而非断言 |
| 大 diff 扫描性能 | Low | 仅扫变更文件、逐文件流式处理 |
| 误报干扰审查者 | Low | 仅报告不阻断，报告段落可读性设计 |
